LLM / assistant documentation — vega-plot/
==========================================

Version: 1

This file is plain-text guidance for humans and coding assistants. The dashboard
runtime (index.html) does not read this file; it only loads meta.json and Vega
JSON. Prefer README.md for end-user documentation; AGENTS.md and agent-guide.json
for structured workflows.

Overview
--------

Human-readable documentation: README.md in this folder (vega-plot/README.md).

For coding assistants: AGENTS.md (workflows) and agent-guide.json (structured
tasks and constraints).

When editing meta.json or Vega-Lite JSON, prefer README.md + AGENTS.md +
agent-guide.json + meta.schema.json together.

Repository layout
-----------------

meta.json
  Dashboard config: page title, defaults, intro HTML, screens (tabs), each
  pointing to Vega-Lite JSON paths.

meta.schema.json
  JSON Schema for meta.json (validation in editors; documents field shapes).

index.html
  Single-page app: fetch meta.json, tab UI, period filter with
  {{YEAR}}/{{MONTH}} substitution in spec URLs, lazy chart load per tab.

vega-spec.json
  Example Vega-Lite v5 spec: mqtt_hive SQL via data.url, CSV format.

events.json
  Example bar chart spec with daily aggregation SQL.

How to add a Vega-Lite file
----------------------------

1. Create a new file under vega-plot/, e.g. my-chart.json.

2. Set "$schema" to "https://vega.github.io/schema/vega-lite/v5.json" for
   editor hints.

3. Use "data": { "url": "<HTTP URL returning CSV>", "format": { "type": "csv" } }
   for rsiotmonitor /sql/ endpoints.

4. Encode the SQL query as the path after /sql/ (spaces and quotes appear
   URL-encoded in practice).

5. Use placeholders {{YEAR}} and {{MONTH}} in the URL where the SQL uses hive
   partition filters year= and month= so the dashboard period control can
   rewrite them.

6. Optional: use literal year=2026 and month=4; the app still rewrites numeric
   year=/month= for backward compatibility.

7. Test in https://vega.github.io/editor/ by pasting JSON and adjusting data.url
   to your server (CORS must allow the page origin).

8. Reference the file from meta.json: screens[].spec (one chart) or
   screens[].charts[].spec (several charts per tab).

How to add a screen in meta.json
---------------------------------

1. Add an object to the "screens" array with a unique "id" (letters, digits, _, -).

2. Set "title" for the tab label; optional "description" or "descriptionHtml"
   for text under the tab.

3. Either set "spec": "relative/path.json" for a single chart, OR set
   "charts": [{ "spec": "...", "id": "slot1", ... }] for multiple charts
   (charts wins if non-empty).

4. Optional "layout": "row" | "stack" or { "flow": "row|stack", "gap": "16px" };
   per-chart "layout": { "span": "half|full|auto", "breakBefore": true } inside
   charts[].

SQL data URL contract
---------------------

Shape:
  Base URL + /sql/ + URL-encoded SQL string. Example host from this project:
  http://HOST:PORT/sql/select ... from mqtt_hive where ... and year={{YEAR}}
  and month={{MONTH}} ...

Placeholders:
  {{YEAR}}  — Substituted with the integer year from the filter (e.g. 2026).
  {{MONTH}} — Substituted with month 1-12 (no zero-padding).

Runtime behavior:
  Before fetch, every "url" field in the Vega spec tree is patched. Requests run
  only when the user opens that tab (lazy load). Changing year/month refetches
  CSV for charts whose spec was already loaded.
